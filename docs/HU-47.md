# HU-47 — Recruiter gestiona ficha del candidato

**Como** recruiter autenticado
**Quiero** subir el CV y completar la ficha de un candidato en el sistema
**Para** registrar su información y hacer seguimiento dentro del proceso de selección.

### Criterios de aceptación

**Autenticación y acceso**

1. El recruiter inicia sesión en `ats-usuarios` con su email y contraseña y recibe un JWT con rol `RECRUITER`.
2. El JWT se envía en cada request a `ats-candidate` como `Authorization: Bearer <token>`.
3. Si el token es inválido o expirado, `ats-candidate` responde con **401 Unauthorized**.
4. Si el usuario no tiene rol `RECRUITER`, `ats-candidate` responde con **403 Forbidden**.

**Crear candidato y subir CV**

5. El recruiter puede crear un candidato nuevo mediante `POST /api/candidates` con los datos disponibles (mínimo: email). El sistema asigna automáticamente el estado inicial `NEW` y responde **201 Created** con el `id` del candidato.

6. El recruiter puede subir el CV del candidato en formato PDF mediante `POST /api/candidates/{candidateId}/attachments` (multipart). El sistema:
   - Almacena el archivo y registra el attachment.
   - Extrae automáticamente el texto del PDF.
   - Pre-llena los campos vacíos del candidato con los datos extraídos (*ver HU-44*):
     - Datos personales: nombre, apellido, email, teléfono.
     - Perfil profesional: último cargo, headline, resumen.
     - Estudios: nivel, título, institución, fechas.
     - Habilidades técnicas y blandas.
   - Responde **201 Created** con los datos del attachment.

7. Si el recruiter necesita re-procesar un CV, puede llamar a `POST /api/candidates/{candidateId}/attachments/{attachmentId}/parse` para forzar el parseo manualmente.

8. Los datos extraídos no sobreescriben campos ya completados; solo llenan los vacíos. Los campos que no se pudieron extraer quedan en blanco y editables.

**Completar y guardar ficha**

9. El recruiter puede revisar y editar cualquier campo antes de guardar. Los datos del CV ya parseado se reflejan en la ficha.

10. Al guardar los cambios, se llama a `PUT /api/candidates/{id}` con el JWT y los datos modificados de la ficha.

11. Si la ficha se actualiza correctamente, el sistema responde con **200 OK** y muestra confirmación.

12. Si hay errores de validación, se muestran bajo el campo correspondiente.

**Editar ficha existente**

13. El recruiter puede buscar candidatos registrados mediante `GET /api/candidates?search={termino}` y seleccionar uno para editar su ficha.

14. Al guardar los cambios, se llama a `PUT /api/candidates/{id}` y la ficha se actualiza.

**Cambio de estado**

15. El recruiter puede cambiar el estado del candidato mediante `PATCH /api/candidates/{id}/status`. Las transiciones permitidas son:

    ```
    NEW → IN_REVIEW → INTERVIEW → SHORTLIST → REJECTED
                                                → HIRED
    ```

    - Solo se puede avanzar hacia adelante en la secuencia.
    - Se permite saltar estados intermedios (ej: `NEW → INTERVIEW`).
    - `REJECTED` y `HIRED` son estados terminales: no se permiten transiciones salientes.
    - No se permite retroceder a un estado anterior.

16. Cada cambio de estado queda registrado en `candidate_state` con fecha, usuario que lo realizó, y el nuevo estado.

**Endpoints involucrados:**

| Método | Endpoint | Descripción |
|--------|----------|-------------|
| `POST` | `/api/auth/login` | Login en `ats-usuarios`, devuelve JWT |
| `GET` | `/api/candidates` | Listar/buscar candidatos (paginated, filterable) |
| `GET` | `/api/candidates/{id}` | Obtener ficha completa de un candidato |
| `POST` | `/api/candidates` | Crear candidato nuevo |
| `PUT` | `/api/candidates/{id}` | Actualizar ficha del candidato |
| `PATCH` | `/api/candidates/{id}/status` | Cambiar estado del candidato |
| `POST` | `/api/candidates/{candidateId}/attachments` | Subir CV en PDF (auto-parsea y pre-llena) |
| `GET` | `/api/candidates/{candidateId}/attachments` | Listar attachments de un candidato |
| `POST` | `/api/candidates/{candidateId}/attachments/{attachmentId}/parse` | Re-parsear CV manualmente |
